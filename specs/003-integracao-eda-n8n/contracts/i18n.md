# Idiomas e propagação do `Accept-Language`

## Idiomas aceitos

| Código | Idioma | Observação |
| --- | --- | --- |
| `pt-BR` | Português (padrão) | Usado quando nada for informado ou o código não for aceito |
| `en` | Inglês | |
| `es` | Espanhol | |
| `fr` | Francês | |
| `zh-CN` | Mandarim (simplificado) | |
| `hi` | Hindi | |
| `ar` | Árabe | Interface em `dir="rtl"` |
| `ru` | Russo | |

## Fluxo

1. O frontend guarda o idioma escolhido e envia `Accept-Language: <código>` em toda chamada à API e no stream SSE.
2. O backend resolve o idioma (código aceito ou `pt-BR`) e o repassa ao prompt do Gemini.
3. O backend inclui `language` nos eventos ao n8n (`dlq-event`, `dispatch-event`, `turismo-clima`).
4. O n8n gera e-mail, WhatsApp e orientações de clima no mesmo idioma.

## Regra para o Gemini

O prompt deve instruir: responder no idioma pedido **sem traduzir nomes próprios de
patrimônios, atrativos, cidades e pratos locais** (ex.: "Cachoeira do Urubu", "Parque
Nacional de Sete Cidades", "Maria Isabel"), podendo explicar o significado entre parênteses.

## Fora do escopo

Mensagens de alerta no Telegram da equipe ficam sempre em PT-BR.
